# Технічний аудит VtxConfig

## Критичні/суттєві проблеми у вихідному варіанті

1. **Код у наданому тексті не компілюється буквально.** Імпорти та частина синтаксису були спотворені при вставці (`javax.swing.;`, `java.awt.;`, тощо). У виправленій версії використано нормальні імпорти.
2. **Порядок ініціалізації списку конфігурацій.** Початковий код викликав `refreshList()` до додавання першої конфігурації, тому порожній список міг залишатися без елемента UI.
3. **JSON-парсер.** `fromJson()` шукав `{`, `}`, `[` і `]` через `indexOf`, не мав повноцінної обробки JSON-рядків/escape-послідовностей і міг неправильно розібрати вкладені структури. Замінено на строгий self-contained JSON parser.
4. **`vtxtable` була неповною.** Генератор не виводив `vtxtable powerlevels`, хоча Betaflight CLI очікує кількість рівнів разом із `powervalues`/`powerlabels`.
5. **E band.** У вихідному коді були частоти `5705 5685 5665 5645 5625 5605 5585 5565`. Поточна документація Betaflight наводить common table як `5705 5685 5665 5645 5885 5905 5925 5945`.
6. **SmartAudio/Tramp power table.** Один набір `0 1 2` був використаний незалежно від протоколу. Це неправильно: Tramp, SmartAudio 2.0 і SmartAudio 2.1 мають різні правила power values. Генератор тепер вибирає таблицю за протоколом; для SA 2.1 явно попереджає, що значення модель-залежні.
7. **`serial` CLI.** Рядок `serial UART 1 ...` був синтаксично неправильним як назва порту. Для Betaflight 2025.12 і раніше порт має бути записаний як `UART1`, `UART2`, тощо. Для 2026.12+ команда `serial` стала read-only, тому генератор показує `set vtx_uart = UARTn` як сучасний варіант.
8. **Небезпечне перетирання serial function mask.** Автоматичний `serial ... 2048/8192` може замінити інші функції порту. Тепер це окремо позначено як optional port setup і не додається за замовчуванням.
9. **Збереження поруч із executable.** Збереження даних у системній per-user теці залишено й зроблено частиною виправленої реалізації.
10. **Send to FC.** Додано Windows COM/CLI workflow: `#` → generated commands → `save` або `exit noreboot`, з підтвердженням перед записом.

## Перевірки

- `javac` — PASS.
- запуск packaged application image через Xvfb — PASS (процес живе, завершений timeout-ом тестового запуску).
- JSON serialize → parse round-trip — PASS.
- escape у JSON-рядках — PASS.
- VTX table CLI містить `powerlevels` — PASS.
- E band перевірено — PASS.
- VTX table JSON проходить стандартний JSON parser — PASS.
- `jpackage --type app-image` — PASS.

## Що не можна чесно підтвердити локально

Фізичний `Send to FC` не тестувався з реальним flight controller/COM-портом у цьому середовищі. Так само не можна підтвердити конкретну VTX power table без моделі VTX; для SmartAudio 2.1 документація прямо вказує на model-specific values.

Windows MSI також не створений локально, бо `jpackage` формує native package для платформи, на якій запускається; Windows MSI потрібно збирати на Windows. Для цього додано `build-windows.ps1` і GitHub Actions workflow.
